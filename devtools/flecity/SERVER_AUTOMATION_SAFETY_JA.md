# FiveM状態に応じた自動実行制御

## 独立した2つの状態

ローカル開発・検証の状態と、実サーバーへの反映可否を分離する。
サーバー停止・接続あり・取得失敗でも、各アプリのLua/JS/SQL/模擬NUI/画像比較/ゲーム/仮想複数人検証を続ける。
プリフォトは既存のユーザー指定PAUSEDを維持する。1アプリの失敗・保留で他アプリを停止しない。

## 実反映の全条件

UPDATE_POLICY.jsonは現在enabled=false、承認済みresourcesは空。新規登録も同じ拒否状態を継承する。
自動反映判定はserver/update-gate.mjs、ローカル証跡を集める処理はserver/automatic-readiness.mjs。

1. 固定の既存テストサーバーD:/FiveM_Test_Serverと登録対象パスが一致し、対象と依存リソースが正常稼働。
2. 認証済みブリッジから、今回のランダム要求ID・サーバーインスタンスに対応した2秒以内のネイティブな0人証明。
3. 対象リソース名・対象パス・初回更新・再起動範囲の明示承認。
4. 現在の厳密なソースハッシュに対応する12時間以内の必須テストが全件PASS。SKIP/NOT_RUN/空のchecksは不合格。
5. 対象ハッシュと一致するバックアップと復旧検証。
6. 台帳から計算した共有アプリ全件、依存リソースの影響、データ非変更・DB移行なし・完全なソース・削除なしの監査。
7. 実行全体を覆う排他制御。他の更新・検証と同時実行しない。
8. ファイル更新直前・実際の切替地点・再起動直前・実際のネイティブ再起動発行地点で再度0人確認。同じサーバーインスタンスであることも必須。

公開info/dynamic/players.jsonは診断用。0人で一致してもネイティブ証明の代用にしない。
null/false/空文字/不正値/不一致/古い情報を0人と解釈しない。全取得拒否はUNREACHABLEとし、プロセス停止と断定しない。
必須スイートはstatic/db/nui/visual/game/virtual-multiplayer。アプリ未対応を推測でPASSとせず、そのアプリの実反映だけを保留する。

## 中断・復旧

PREFLIGHT → READY → COMMITTING → FILES_REPLACED → RESTARTED → COMPLETE の状態をジャーナルへ保存する。
1人以上、不明、インスタンス変更、依存停止、バックアップ破損、未承認、試験不足ならHELD。
切替を試みた後の異常は、書込みがなかったと推測せずPOSSIBLE_PARTIAL_WRITE/復旧レビュー待ちとして扱う。
更新後に接続者が現れた場合、再起動だけでなく自動ロールバックも中止する。実行中のリソースやプレイヤーへ追加の変更をしない。
復旧には同じインスタンス・新鮮なネイティブ0人・対象リソース停止・対象承認・元バックアップIDとハッシュの一致を再確認する。
復旧直前に再確認してから既存のreplaceTreeを使う。サーバー全体や対象外リソースの起動・停止・再起動は行わない。

## ブリッジと現在の停止境界

既存flecity_validation_bridgeを再利用するローカル0.2.0-dev案にobserve_statusを追加した。
GetNumPlayerIndicesと許可されたリソース状態だけを返す。プレイヤー識別子・DB・ネットワークイベント・任意コマンド・起動/再起動機能は追加していない。
既存config.allowedで明示許可されなければ観測要求も拒否する。旧ブリッジの自己診断許可を更新・再起動許可へ拡大しない。

**この変更は専用workspace内だけ。既存サーバーのブリッジは更新していない。**
状態機械と一時ファイル用バックエンドは模擬検証済み。実ファイル更新とネイティブな「0人確認＋対象再起動」を結ぶ実テストサーバー向けアダプターは未有効・未実装。
既存applyにautomatic=trueを渡しても拒否する。手動applyを自動反映として流用しない。
現在は状態観測・反映可否の報告まで。実反映の初回承認を求める前に、対象・厳密な候補・必須PASS・バックアップ・復旧・リソース起動時の既存DB非変更監査・ブリッジ差分とアダプターを具体化してレビューする。
停止中のサーバーを自動起動する処理、サーバー全体の再起動、既存プレイヤーデータの変更経路はない。

## ローカル検証

- Lua/JS/manifest/callback/SQLソース検査は既存アダプターを使用。
- SQLはTCP無効・固有named pipe・固有datadirの使い捨てMariaDBのみ。既存サービスや既存DBに接続しない。
- 正常終了かつSQL検証でFAILがない専用datadirだけを削除し、ログとfixture.jsonは残す。失敗・終了不明のデータは保持する。
- BASE/LINKのNUIは合成データ。WAVE/フレプリの未登録シナリオはNOT_RUN。
- 画像はユーザー承認済みui-baselines/<app>/approval.jsonとPNGだけを使用。画像ハッシュ・ソース一致・寸法・ノイズ閾値・動的マスクを検査。基準なしはNOT_RUN、基準の自動作成/更新なし。
- 仮想複数人は実LINK Luaハンドラーに4仮想IDでロビー、2仮想IDでコネクトフォーを投入。招待コード、重複・権限・手番・不正token・勝敗・退出を検査。固定seed=20261031。決定的な交互投入であり、実ネットワーク同期や複数FiveMクライアント試験ではない。
