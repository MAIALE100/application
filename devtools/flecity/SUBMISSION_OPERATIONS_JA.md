# 運営提出優先モード

2026-10-31の最新ユーザー指示を優先し、LOOP＋LINK（共同提出） → BASE → WAVEの順に完成へ近づける。
プリフォト/フレプリは提出済みの保守枠。大規模機能/UI変更を行わない。プリフォトの既存255差分PAUSEDは維持する。
Photo Diaryは別の保留枠。候補アプリの不足として混ぜない。

## 作業と提出可否

方針はMIGRATION_STATE.json、提出条件と残作業はSUBMISSION_STATUS.json、根拠はreports/submission-priority-20261031/。
完成率を推測で数値化しない。コード実装済み、ローカル確認済み、実機未確認、提出不可を分ける。
新機能よりデータ安全性、クラッシュ/通信、タイミング、軽量化、小規模UI修正を優先する。
LOOP/LINKは同じソースを使う。共通コード変更は両アプリの回帰を必須とする。

提出候補には重大不具合レビュー・必須自動検証・FiveM実機・DB権限・日本語UI・既存データ/他アプリ影響・日本語資料・ZIP検査すべてのPASSと同じソースハッシュが必要。
ZIP検査以外の条件が揃った後、新規の検査用ZIPを作成・全件検査し、最後に「提出候補」へ昇格する。未検査のZIPを提出候補と呼ばない。
実機や未知の仕様を勝手にPASSへ変更しない。候補でもmayPublish=false、実提出・公開はユーザー承認後。
現在4アプリとも提出不可。最終ZIP未検査・実機未実施のため候補ZIPは生成しない。

## 無人のローカル開発

既存02:00/13:00 JSTタスクを継続し、優先アプリから1件の小さなバグ修正/回帰改善を選ぶ。修正不要なら検証だけを実行する。
通常の検証: powershell -NoProfile -ExecutionPolicy Bypass -File devtools/flecity/automation-run.ps1

安全なコード変更は、直接アプリを書き換えず次の提案形式を使う。

    {
      "app": "loop",
      "reason": "修正理由",
      "changes": [{"path":"web/play/app.js", "baseSha256":"変更前SHA-256", "content":"変更後の全テキスト"}]
    }

.flecity-dev/proposals/<UUID>.jsonへ保存し、上記入口に -Proposal <提案JSONの絶対パス> を渡す。
1回1提案・最大5ファイル。新規テキストのみbaseSha256=null。削除・バイナリー・大規模追加は行わない。
既存アプリ内の未コミット変更・他のステージ済み変更・基準ハッシュ不一致・保守/保留アプリ・パス逸脱は拒否し、他アプリの検証を続ける。

既存OS mutexを提案適用→回帰→ローカル保存まで保持する。サーバーの状態はローカル作業を阻害しない。
保存前に共通テストPASS、対象の静的/NUI、LINKのゲーム/仮想複数人、共有アプリ全件の同じソース回帰を確認する。
DB/画像/実機等の未完了は記録し、提出・実反映のゲートを緩めない。NUIアダプター未実装のWAVEは、自動修正の保存条件も未達となる。
失敗は提案が書いたバイトと一致する自分の変更だけを戻す。途中のユーザー編集があれば自動復元せずbefore.jsonと両方の内容を保全してレビュー待ち。
書込み中の障害も完全適用と推測せずAPPLY_FAILED_REVIEWと記録する。

検証済みコードは既存checkpointを使うアプリ別ローカルGitと、対象ファイルを明示した親Gitへ保存する。
アプリ別Gitは.flecity-dev/projects/<app>/git、変更前/結果は.flecity-dev/development/<ID>/。
親Gitの共通管理領域に権限が不足する場合、アプリ別Gitの保存SHAを報告し、APP_LOCAL_SAVED_PARENT_PENDINGとして親保存を保留する。既存変更を破棄して解決しない。

## 実サーバーと禁止事項

UPDATE_POLICY.jsonは無効・初回承認0件を維持する。接続0人だけでは反映しない。
SERVER_AUTOMATION_SAFETY_JA.mdの全条件と事前承認前に、実リソース更新・再起動を行わない。
GitHub、原本/バックアップの変更、実DB操作、サーバー起動/全体再起動、公開/提出、料金変更は禁止。
レポートには各アプリの実装/検証状態、既知不具合、実行テスト、提出可否、必要なユーザー確認だけを日本語で保存する。
