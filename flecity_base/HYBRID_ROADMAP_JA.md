# BASE ハイブリッド型への拡張方針（開発ブランチ用）

更新日: 2026-10-30
対象ブランチ: `base/workspace-dev`
リリース状況: **設計確定・未実装**。運営提出用の `release/base-v0.10.0-beta.1` と配布ZIPには影響させない。

## 目的

既存のメモ・在庫・タスク・会計・電卓をそのまま直感的に使える状態を維持し、必要なワークスペースだけが独自項目を追加できる「ハイブリッド型」へ段階的に拡張する。

### 非目標

- Excel互換のセル編集・任意の数式実行・自由なSQL・スクリプトの入力は実装しない。
- 銀行残高・会社口座・ox_inventoryなどの実経済・実在庫は変更しない。
- 既存ワークスペースを自動変換・消去しない。
- 先行公開β版に未検証コードを混ぜない。

## 現状確認（2026-10-30）

- `flecity_base/sql/schema.sql`: 在庫は固定列 `name/category/quantity/minimum_quantity/unit` 等を保持。カスタムフィールド用のテーブル・列は未実装。
- `flecity_base/config.lua`: 個人・企業・クルー・チーム・プロジェクト・カスタムのテンプレートは、現時点でほぼ共通のモジュール構成。
- `flecity_base/web/app.js`: メモ・在庫・タスク・会計に検索・フィルタ・増分表示を実装済み。電話画面の軽量性を維持する。
- `flecity_base/server/main.lua`: DB書込みとサーバー側のロール判定がある。拡張項目も**毎回サーバー側**で検証すること。

## 開発順序

### P0: データ安全性とテスト

1. 在庫更新と履歴記録をトランザクション化し、競合操作と一部失敗を検証する。
2. 招待・上限判定などの競合操作をテストする。
3. 管理権限の変更・削除操作の監査粒度を明確化し、必要な監査記録を追加する。
4. UIが大量件数でも軽量に動くことを確かめる。実機テストを必要とする項目は未検証として区別する。

### P1: オプション項目（最初は在庫だけ）

- 従来の「商品名・数量・単位・最低数・カテゴリ」は常にそのまま使える。
- OWNER / MANAGERのみが項目定義を追加・変更・非表示にできる。MEMBERは許可された既存のデータ入力・参照だけ。
- 最初の対象は **在庫**。1ワークスペースあたり最大6個の追加項目を目安に、`文字列 / 数値 / 日付 / チェック` 型に限定する。
- 例：「仕入先」「保管場所」「単価」「賞味期限」「確認済み」。
- 新規項目は原則任意入力。既存レコードの値がなくても開ける。標準項目と既存データに影響させない。
- スマホ画面では追加項目を折りたたみ表示し、基本情報は最初から見える構造とする。
- 項目定義・値は専用のマイグレーションを設け、削除はまず「非表示」を標準とする。復元不能な自動削除はしない。
- 文字数、数値範囲、日付形式、項目数、値の総サイズをサーバー側で制限する。
- ユーザー入力をHTMLに直接流し込まない。既存のescape処理・パラメータ化SQLを利用する。
- 他人のworkspace IDやrecord IDへの操作は、ロール確認とレコード所属確認をセットで行う。

### P2: 既存モジュールへの段階展開

- 在庫で安定性とUIを検証後、**タスク → 会計 → メモ**の順に追加項目の対応可否を判断する。
- 「メモ」は既に柔軟な本文・タグがあり、必ずしも独自項目を増やさなくてよい。
- 会計の任意項目は記録用途のみに限定し、金額計算や現実の送金処理には利用しない。
- 既存の固定列とカスタム項目の表示・編集に一貫性を保つ。

### P3: 使いやすさ

- テンプレートごとの初期表示を差別化する（例：企業は在庫/会計、プロジェクトはタスク/メモ）。**非表示にするだけでデータ・権限は変更しない**。
- CSNを知らなくても招待できる導線を検討する（オンライン一覧の公開範囲・個人情報・名前重複に配慮）。
- OWNER譲渡、繰り返しタスク、通知はそれぞれ独立したテスト対象として追加。
- 操作ログ・復元・リアルタイム反映は、通信負荷とDB容量を計測してから導入する。

## リリースゲート

- ベータ版と同じ構成を保ち、新規変更を加えても既存のデータで起動できる。
- 項目未設定のBASEは旧版と同じ操作が可能。
- 不正型・不正ID・他人のBASEへの参照/編集をサーバーが拒否する。
- 同時更新で在庫と履歴が不一致にならない。
- 再起動後も追加項目・値が保存される。
- オプション項目の追加/非表示で過去の記録が消えない。
- `base_selftest`、Lua/JS構文、マイグレーション、複数人実機の各結果を個別に記録する。
- 運営提出用ZIPの更新は、上記を満たすまで行わない。

## バージョン管理

- 設計と開発：`base/workspace-dev`
- 運営提出済み候補：`release/base-v0.10.0-beta.1`
- 新機能は新しいマイナーバージョン候補として開発する。現行β ZIPの再利用・上書きはしない。
