Flecity Games PARTY v1.0.0
運営様向け 導入方法

この度はPARTYの導入をご確認いただき、ありがとうございます。
本データは、既に導入済みの一人用ゲームアプリ「LOOP」を維持したまま、
同じ独立resource「flecity_games」に複数人用ゲームアプリ「PARTY」を追加する更新版です。

LB Phone本体、Qbox本体、既存アプリ本体のファイルを直接編集していただく必要はありません。

■ 今回の提出内容
・既存アプリ「LOOP」v1.0.0相当の機能を維持
・LB Phone用複数人ゲームアプリ「PARTY」v1.0.0
・PARTY内ミニゲーム 合計15種

・PARTY+：7日 / 50,000

・ルーム作成 / 4桁コード参加 / Ready / ホスト管理
・切断 / 再接続 / ホスト移行 / timeout / cleanup
・LB Phone App Storeから無料ダウンロード

LOOP・PARTYともに初期状態で強制インストールせず、
プレイヤーがLB PhoneのApp Storeから必要な時に無料でダウンロードする方式です。

■ 前提
・qbx_core：QBox 2.5.4
・oxmysql
・player identifier：citizenid = CSN
・LB Phone：2.9系

■ 更新手順
1. 念のため、現在の「flecity_games」フォルダをバックアップしてください。

2. ZIP内の「flecity_games」フォルダで、現在の「flecity_games」を更新してください。

3. サーバー稼働中の場合、サーバーコンソールで以下をご実行ください。

refresh
restart flecity_games

通常、サーバー全体の再起動は不要です。
server.cfgの「ensure flecity_games」は既存のままで、PARTY用のensure追加は不要です。

■ LOOPの既存データ
今回の更新では、LOOPのidentifierや既存DB仕様を変更しません。
既存のスコア、BEST、セーブ、実績、Daily、ランキング等は維持する前提です。

■ データベース
PARTYのRoom状態はサーバーメモリ上で管理します。
PARTY+の有効期限・自動更新状態は「flecity_game_subscriptions」に保存します。

起動時に必要なテーブル・不足項目を自動確認します。
通常はSQLの手動実行は不要です。
既存データに対するDROP TABLE / TRUNCATE TABLEは実行しません。

■ PARTY+決済
・プレイヤー本人のbankから50,000をserver側で減算します。
・有効期間は7日です。
・自動更新ONの場合、期限後の次回PARTY利用時に1期間だけ更新を試行します。
・自動更新を停止しても現在の期限までは利用できます。
・売上はWEAZEL企業口座「weazel」へ入金します。
・企業口座providerはauto判定です。
  - Renewed-Bankingが起動中の場合は同resourceを使用します。
  - それ以外でqb-bankingが起動中の場合は同resourceを使用します。
・WEAZEL企業口座への入金に失敗した場合、購読を成立させずプレイヤーへ返金します。
・入金後に購読DB保存が失敗した場合は、企業口座入金の取り消しとプレイヤー返金を試行します。
・企業口座連携が利用できない状態で50,000だけが消える設計にはしていません。

■ 正常起動の目安
サーバーコンソールに概ね以下が表示されます。

[FlecityGames] database schema ready
[FlecityGames] LB Phone callbacks registered .../...
[FlecityGames] startup preflight READY_FOR_LIVE_TEST

■ 確認用コマンド
必要な場合のみ、サーバーコンソールから以下をご利用ください。

game_status
game_preflight
game_selftest
game_party_status
game_healthcheck

■ 導入後の最小確認
1. LB PhoneのApp StoreにLOOPとPARTYが表示されること
2. LOOPが従来どおり起動できること
3. PARTYを無料でダウンロードできること
4. 2台以上の端末で、Room作成・4桁コード参加・Ready・ゲーム開始ができること
5. PARTY+購入時にプレイヤーbankから50,000減算されること
6. WEAZEL企業口座へ50,000入金されること
7. PARTY終了後もLOOPの既存記録・セーブが維持されていること

■ 切り戻し
問題がございましたら、更新前にバックアップしたLOOP版「flecity_games」へ戻し、

refresh
restart flecity_games

をご実行ください。

PARTY用DBテーブルを削除する必要はありません。

運営様側の作業を最小限にできるよう、
通常の更新は「flecity_games」の差し替えと「restart flecity_games」のみで完了する構成です。
