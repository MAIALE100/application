■ データベース
PARTYのRoom自体はメモリ管理で、永続Roomテーブルは追加しません。
PARTY+のみ citizenid(CSN) / active_until / auto_renew を保持する flecity_game_subscriptions を自動作成します。
SQLの手動実行は通常不要です。
DROP TABLE / TRUNCATE TABLE はありません。

■ PARTY+決済
bankから50,000をserver側で減算します。
現提出候補では50,000は経済sinkで、会社口座等への売上振替先は未設定です。
売上振替が必要な場合は、運営仕様確定後に決済成功eventへ口座処理を接続できます。

更新前の flecity_games へ戻し、refresh → restart flecity_games で切り戻せます。

[実機確認: 順番制ゲームのアプリ終了]
□ TELEPHONEの手番中にPARTY/Phoneを閉じると、その手番を即skipして次の開いている参加者へ進む
□ BOMBの手番中にPARTY/Phoneを閉じると、閉じた参加者を飛ばして次へ進む
□ TIC-TAC中にPARTY/Phoneを閉じると、相手の不戦勝として結果確定する
□ 上記でRoom自体からは退出せず、次Roundには通常参加できる
※ FiveM複数クライアント実機で未確認の間は合格扱いにしない


PARTY+ app/phone close実機確認（未検証）:
- NG WORDで説明役close時に即終了し、回答役close時は残り回答者だけで完了できること。

【実機未検証：アプリ終了と遅延callbackの競合】
□ 2台以上でラウンド中、入力送信とほぼ同時にPARTYアプリまたはPhoneを閉じる
□ close後に遅れて到着したReady／開始／各ゲームsubmitがサーバー状態を変更しない
□ 閉じた端末はRoom所属を維持したまま appOpen=false になり、通常の再openで同じRoomへ復帰できる
□ Hostを閉じた場合、開いている別参加者へHostが移り、旧Host再open後もRoom操作が破綻しない
※ FiveM＋LB Phone複数クライアントでのタイミング依存確認が必要。未実施の間は成功扱いにしない。


【実機未検証：閉じたHostと後参加者のHost復旧】
□ HostがPARTY/Phoneを閉じ、既存参加者も全員アプリを閉じた状態にする
□ その後、新しい参加者がRoomへJoinすると、その開いている参加者へHostが即移行する
□ 新Hostが追加の再openやサーバー再起動なしでゲーム選択・開始できる
□ 旧Hostを再openしてもHost権限を奪い返さず、通常参加者としてRoomへ復帰する
※ FiveM＋LB Phone複数クライアントで未確認の間は合格扱いにしない


【実機未検証：閉じた端末へのRoom push抑止】
□ PARTY/Phoneを閉じた参加者へ partyUpdate / DRAW stroke等のRoom pushが送信されない
□ 開いている他参加者には同じ更新が即時反映され、Round進行が止まらない
□ 閉じた参加者を再openするとGetRoomで最新状態へ復帰し、server再起動を必要としない
□ game_party_statusで閉じた参加者のappOpen=falseが維持される
※ FiveM＋LB Phone複数クライアントで未確認の間は合格扱いにしない


## 同時入力ゲームのapp/phone close（未検証・2026-10-24）
- REACTION / STOP! BATTLE / VOTE / MAJORITY / MINORITY / WORD WOLF / LIAR で、未入力者がPARTY/Phoneを閉じた場合、その端末を回答待ち人数から即除外し、残るapp-open参加者が全員入力済みならtimeoutを待たず結果確定すること。
