# Flecity JAM 0.2.0-test 品質確認の現在地

更新日: 2026-11-16 JST。**0.2.0-testは開発・検証中であり、住民向けリリース候補として完成したとは判定していません。** この文書の試験状態は0.2.0-testのコードを対象とします。過去版のPASSを新しい版の実機PASSへ繰り越しません。

自動試験の最終件数は、ソースを固定した後に別添の実行レポートで集計します。試験の入口は[tests/README.md](../tests/README.md)、実機の判定条件は[実機チェックリスト](LIVE_CHECKLIST_JA.md)を参照してください。事前の5楽器・音源波形監査は別添 `release-candidate/QA/JAM_5_INSTRUMENT_AUDIO_AUDIT_JA.md` にあり、修正前の測定値を現在の実機品質と混同しません。

## 確認できている事実

- 0.1.0-testでは、ユーザーがFiveMでメトロノームとピアノC4を実際に聴きました。初回に無音だった条件の原因は未確定です。これらは0.2.0-testの発音PASSではありません。
- 現在のテストサーバーには0.1.0-testと画面互換修正が設置されています。0.2.0-testのソース変更を反映した実機試験は、この文書の更新時点では未実施です。
- 0.2.0-testのコードには、起動時の再読み込み、通信の短い再試行、音源取得の時間上限、音声再開の再確認、消音設定の保持、演奏セッション切替時の古い送信キューの隔離を追加しました。機能が実FiveMで安定するかは今後の試験で判定します。
- ベースの初期オクターブは1で、最初の有効音はE1（標準Dキー）です。ピアノの弱いvelocity層（v2）は、同音高の強い層との録音RMS比でゲインのメタデータを補正しました。音源ファイル58件の内容は変更していません。実際の聴感の良さは未判定です。
- 音声診断の `voices` は発音中、`nodes` はリリース中の余韻を含む確保済みノードです。128の上限は `nodes` に適用されます。短い余韻の間に `nodes` が `voices` より多いことを、ただちに音の残留不具合と判定しません。

## 0.2.0-testの実機判定待ち

| 項目 | 現在の判定 | 必要な証拠 |
|---|---|---|
| 初回・再表示・再接続での発音 | NOT_RUN | FiveM CEFでメトロノームと各楽器の発音を繰り返し聴取。無音時の再試行と消音設定も確認 |
| 5楽器の音質 | NOT_RUN | 弱強・低高音・連打・和音・長音・余韻を実際に聴取し、録音や所見を残す |
| 複数人の合奏 | NOT_RUN | 別の実クライアントで同時演奏、同一楽器、互いの音を確認 |
| 距離・Routing Bucket・途中参加 | NOT_RUN | 位置移動、範囲外消音、別Bucket遮断、再接近と長音中の途中参加を実機確認 |
| 通常VC・PTT・無線 | NOT_RUN | 実際のVoice入力とJAM演奏を同時に操作し、会話とキー競合を確認 |
| 物理MIDI機器 | NOT_RUN | 実機の接続、Note On/Off、ベロシティ、ペダル、抜き差しを確認。機器なしなら未確認を維持 |
| 演奏Prop・アニメーション | NOT_RUN（既定OFF） | 必要時だけ既定の `Presentation=false` を隔離試験で変更し、自他の表示と解除を確認 |
| FiveM負荷・長時間使用 | NOT_RUN | resmon、FPS、メモリ、音声ノード、イベント量と残留音を継続計測 |

ブラウザー、Fengari、モック、音源の数値測定は実機の音声出力や複数人の体験を証明しません。現地で行えなかった項目はPASSではなくNOT_RUN、環境条件で実行不能ならBLOCKED、実行して基準を満たさなければFAILと記録します。

## 更新時の保護条件

JAMだけを対象にする。現行のJAM全ファイルを固定済みSHA256一覧と照合し、差があれば `CONFLICT_STOP`。設定を勝手に移行せず、全体バックアップと復元経路を確保してからJAM単体を更新する。WAVE、Voice、他リソース、既存DB、サーバー全体は変更しない。テストサーバーへの実適用と本番公開は別の判定です。
