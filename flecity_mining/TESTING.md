# Flecity Mining - TESTING

## 実機スモークテスト（最優先）

通常鉱山の変更後は、異常系を広く試す前にこの順で1周だけ通します。
途中で1項目でも失敗した場合は、その時点で重労働区画・危険坑道のテストへ進みません。

1. `ensure flecity_mining` 後にコンソールエラーがない
2. `mining_selftest` が PASS
3. `mining_healthcheck` で `qbx_core=started`
4. `mining_configcheck` が PASS
5. マップの「公共鉱山」ブリップから受付へ到達できる
6. 受付で開始し、GPSが採掘地点へ設定される
7. 壁面ドリル演出（向き・prop・音・粉塵）を確認して1回採掘し、原石が1〜2増える
8. 同じnodeの即時再採掘がクールダウンで拒否される
9. 原石12個まで採掘し、12を超えずGPSが選鉱設備へ変わる
10. 全量選鉱し、原石0・精製鉱石12個になる
11. 受付へ戻って売却し、cashだけが表示額ぶん増える
12. 売却直後の再売却で追加報酬が発生しない
13. Gまたは `/mine_end` で正常終了し、GPSルートが消える

### 1周テスト記録テンプレート

```text
開始時cash:
終了時cash:
実受取額:
開始→売却完了:
採掘回数:
選鉱結果:
受付座標: OK / 要調整
採掘node: OK / 要調整
選鉱設備: OK / 要調整
GPS誘導: OK / NG
アニメーション: OK / 要調整
txAdminエラー: なし / あり
初見UXメモ:
```

実受取額は「終了時cash - 開始時cash」と売却通知額が一致することを確認します。
このスモークテストが通ってから、下記の境界ケース・悪用確認へ進みます。

## 起動確認

1. ensure qbx_core
2. ensure flecity_mining
3. サーバーコンソールでエラーがないこと
4. マップに「公共鉱山」ブリップが出ること

## 正常系

### 1. 受付

- 受付へ行く
- [E] 鉱山作業を開始
- 開始通知が出る
- 最寄りの採掘地点へGPSルートが自動設定される
- /mine_status で 原石 0/12

### 2. 採掘

- 採掘地点でE
- 約8.5秒固定される
- 完了後、原石が1〜2増える
- 同じ地点を直後に再使用するとクールダウン通知
- 別地点では採掘可能
- 採掘完了後、GPSがクールダウン中の地点を避けて利用可能な近い採掘地点へ切り替わる

### 3. 満載

- 原石12個まで採掘
- 12個を超えない
- 満載時は追加採掘できない
- 満載になると選鉱設備へGPSルートが切り替わる

### 4. 選鉱

- 選鉱設備へ移動
- Eで約10秒
- 原石が0になる
- 鉄/銅/銀/金へ変換される
- 原石が0かつ精製鉱石がある場合、受付/買取へGPSルートが切り替わる
- /mine_status で内訳確認

### 5. 売却

- 受付へ戻る
- Eで約3秒
- cashが増える
- 精製鉱石が0になる
- 次の採掘地点へGPSルートが戻る
- 同じ鉱石を二重売却できない

## 異常系 / 悪用確認

- 受付から離れてstartイベントを送っても開始しない
- 死亡/行動不能状態で受付からstartShiftを直接送ってもセッションを開始しない
- 採掘地点から離れてbeginMineを送っても開始しない
- 存在しないnodeIdを送っても採掘できない
- 作業完了前にfinishActionを送っても報酬が出ない
- 設定時間より最大650ms早いfinishActionでも拒否される（旧猶予窓の再発防止）
- 他のtokenでfinishActionしても報酬が出ない
- 採掘中に死亡するとキャンセルされる
- 死亡/行動不能状態のまま採掘・選鉱・売却イベントを送っても開始しない
- QBoxのダウン/last stand状態（pedのHPが0より大きい場合を含む）でも採掘・選鉱・売却を開始できない
- 作業終了直前に死亡してもサーバー側で完了を拒否し、原石/精製鉱石/現金が増減しない
- 採掘中にresourceをrestartしてもプレイヤーがFreezeされたままにならない
- 採掘/選鉱/売却中にadmin teleport等で作業地点から強制移動された場合、クライアント側も即中断してprop・音・Freezeを解除し、報酬/在庫変化が発生しない
- qbx_core停止時に現金が増えない
- 支払い失敗時に精製鉱石が消えない
- 連打しても同時に複数アクションが開始しない

## 坑道・壁面ドリル実機確認（v0.3）

採掘場所は Great Chaparral の標準Abandoned Mineへ移行しています。
坑道内部の初期node座標はテスト値なので、最初の実機では経済バランスより位置・演出確認を優先します。

確認:

- 「公共鉱山」ブリップがGreat Chaparralの坑道入口へ移動している
- 受付が坑道入口付近にあり、地面へ埋まっていない
- 選鉱設備が入口外側で自然な位置にある
- 坑道内部が読み込まれる
- 採掘地点の巨大矢印がなくなり、4m以内の小さい目印だけ表示される
- Eで採掘するとプレイヤーが岩壁へ向く
- Fleecaドリルpropが手に表示される
- resource起動後の「最初の1回」だけドリル開始が数秒余計に遅くならない（asset preload確認）
- ドリルアニメーションが壁面に対して不自然でない
- 掘削音が鳴る
- 壁面付近に粉塵/岩片エフェクトが出る
- 終了/死亡/resource restart後にドリルprop・音・Freezeが残らない
- `restart flecity_mining` を数回繰り返しても坑道IPL/ドリルanimation/PTFXのcleanupでエラーが出ず、再起動後に坑道とドリル演出を再ロードできる
- 採掘・選鉱・売却中の画面下部に `[G] 中断` が表示される
- 各作業中に [G] を1回押すと任意中断でき、prop・音・Freezeが即解除される
- [G] 中断後に原石・精製鉱石・現金が増減せず、同じ操作を改めて正常開始できる
- 採掘をG中断→すぐ別nodeで再開しても、旧nodeの粉塵が残らず、新nodeの粉塵が途中で消えたり二重発生しない
- 採掘中にサーバー側sessionが無効化された場合も、state同期後すぐ演出・Freezeが解除される
- 6nodeすべてが通路内にあり、壁や地面へ埋まっていない

### 座標調整コマンド

テスト中は `Config.DevTools = true`。

壁の前で立ち位置を決めたら:

```
/mine_devpos
```

F8 consoleへ以下の形式で出ます。

```lua
stand = vector3(x, y, z), heading = 123.45
```

その位置から掘りたい壁へ正面を向いて:

```
/mine_devwall
```

5m以内の壁面へraycastし、

```lua
target = vector3(x, y, z)
```

を出力します。

スクリーンショットとこの2行があれば、`config/locations.lua` のnodeを直接差し替えられます。

## 境界ケース

明日の実機確認では正常系の後に以下も確認します。

- 採掘中に `restart flecity_mining` してFreezeが解除される
- restart後に受付から新しい作業を正常開始できる
- 選鉱中に死亡しても原石が勝手に減らない
- 売却中に死亡しても精製鉱石が勝手に消えない
- 作業中にEを連打しても二重処理されない
- 採掘・選鉱・売却のサーバーアクション中に `endShift` を直接送ってもセッションを終了できない
- 満載直前に2個抽選されても容量12を超えない
- `qbx_core` が停止/再開した場合、停止中に支払いだけ成功する状態にならない
- 設定ファイルの不正値は `mining_configcheck` で検出される
- `mining_configcheck` がFAILになった状態では、既存セッションでも新しい採掘・選鉱・売却を開始できない
- 作業開始後に設定異常を検出した場合、finishAction時に処理を中断し、原石・精製鉱石・現金を変更しない
- 作業開始後にキャラクター切替を行っても、旧キャラクターの原石/精製鉱石を新キャラクターで引き継げない
- キャラクター切替後は旧セッションが破棄され、受付から新規作業を開始できる

### 設定事故テスト（本番では行わない）

テスト環境で必要な場合のみ、設定を一時的に不正値へ変更し、
resource再起動時に新規受付が安全停止することを確認します。

検出対象:

- 空の鉱石テーブル
- 重複した鉱石ID
- 空・未設定・文字列以外の鉱石id/label（完了通知・精算内訳の実行時エラー防止）
- 0以下のweight
- 小数weight（例: 12.5）でも選鉱がエラーにならず、比率として正常に抽選される
- 小数weightを設定した状態でも `mining_economy` がエラーにならず、weight合計・確率・期待値を表示できる
- 負のvalue
- 0/小数の容量
- 容量・作業時間・クールダウン・距離許容値・採掘量を数値文字列（例: `"12"`）にした場合もFAILになる（実行時の型エラー防止）
- 1000を超える容量（選鉱ループの過大化を防ぐ安全上限）
- min > max の採掘量
- 異常な作業時間
- 重複した採掘node ID
- 文字列・小数・0以下の採掘node ID（node IDは1以上の整数のみ許可）
- 不正な座標
- 過大なサーバー距離許容値


## 受付からの作業終了 UX

未処理・未売却の鉱石がない状態で受付へ戻る。

- 受付に `[E] 作業状況を確認  [G] 鉱山作業を終了` が表示される
- Gで作業終了できる
- 終了後は採掘地点へのGPSルートが消える
- 再度Eで新しい作業を開始できる
- 原石または精製鉱石が残っている場合は、既存のサーバー側保護により終了できない

`/mine_end` は引き続き補助コマンドとして利用可能。
