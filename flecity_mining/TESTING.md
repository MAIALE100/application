# Flecity Mining - TESTING

## 起動確認

1. ensure qbx_core
2. ensure flecity_mining
3. サーバーコンソールでエラーがないこと
4. マップに「公共鉱山」ブリップが出ること

## 正常系

### 1. 受付

- 受付へ行く
- [E] 鉱山作業を開始
- 開始通知が出る
- 最寄りの採掘地点へGPSルートが自動設定される
- /mine_status で 原石 0/12

### 2. 採掘

- 採掘地点でE
- 約8.5秒固定される
- 完了後、原石が1〜2増える
- 同じ地点を直後に再使用するとクールダウン通知
- 別地点では採掘可能
- 採掘完了後、GPSがクールダウン中の地点を避けて利用可能な近い採掘地点へ切り替わる

### 3. 満載

- 原石12個まで採掘
- 12個を超えない
- 満載時は追加採掘できない
- 満載になると選鉱設備へGPSルートが切り替わる

### 4. 選鉱

- 選鉱設備へ移動
- Eで約10秒
- 原石が0になる
- 鉄/銅/銀/金へ変換される
- 原石が0かつ精製鉱石がある場合、受付/買取へGPSルートが切り替わる
- /mine_status で内訳確認

### 5. 売却

- 受付へ戻る
- Eで約3秒
- cashが増える
- 精製鉱石が0になる
- 次の採掘地点へGPSルートが戻る
- 同じ鉱石を二重売却できない

## 異常系 / 悪用確認

- 受付から離れてstartイベントを送っても開始しない
- 採掘地点から離れてbeginMineを送っても開始しない
- 存在しないnodeIdを送っても採掘できない
- 作業完了前にfinishActionを送っても報酬が出ない
- 他のtokenでfinishActionしても報酬が出ない
- 採掘中に死亡するとキャンセルされる
- 死亡/行動不能状態のまま採掘・選鉱・売却イベントを送っても開始しない
- 作業終了直前に死亡してもサーバー側で完了を拒否し、原石/精製鉱石/現金が増減しない
- 採掘中にresourceをrestartしてもプレイヤーがFreezeされたままにならない
- qbx_core停止時に現金が増えない
- 支払い失敗時に精製鉱石が消えない
- 連打しても同時に複数アクションが開始しない

## 現地確認が必要な項目

座標はDavis Quartz標準マップを前提にしています。

- 受付マーカーが地面に埋まっていないか
- 6採掘地点が岩/壁の近くに自然に見えるか
- 選鉱設備マーカーが実景と合っているか
- WORLD_HUMAN_HAMMERING が地形に対して不自然でないか
- WORLD_HUMAN_WELDING が設備に対して不自然でないか

座標・演出は現地スクリーンショットを見ながら調整します。

## 経済テスト

最低3セット計測:

- 1ロード(原石12個)の所要時間
- 1ロードの売上
- 30分換算時給

初期値は仮設定です。
本番の金策順位に合わせて `config/economy.lua` の単価と `config/gameplay.lua` の作業時間を調整します。

## 明日の初回バランステスト

1. 所持金を記録
2. 受付で作業開始
3. 原石を満載まで採掘
4. 選鉱
5. 全量売却
6. 所要時間と受取額を記録
7. これを3周行う

記録する値:

- 1周の所要時間
- 1周の報酬
- 30分換算の推定収益
- 採掘が単調すぎる/忙しすぎるか
- 採掘ポイント間の移動感
- マーカー/受付/選鉱設備の座標ずれ
- 初見でも次に何をするか分かるか

報酬値の調整は `config/economy.lua` の `value` だけで可能です。
抽選比率を変える場合は `weight` を調整します。


## 境界ケース

明日の実機確認では正常系の後に以下も確認します。

- 採掘中に `restart flecity_mining` してFreezeが解除される
- restart後に受付から新しい作業を正常開始できる
- 選鉱中に死亡しても原石が勝手に減らない
- 売却中に死亡しても精製鉱石が勝手に消えない
- 作業中にEを連打しても二重処理されない
- 満載直前に2個抽選されても容量12を超えない
- `qbx_core` が停止/再開した場合、停止中に支払いだけ成功する状態にならない
- 設定ファイルの不正値は `mining_configcheck` で検出される
- 作業開始後にキャラクター切替を行っても、旧キャラクターの原石/精製鉱石を新キャラクターで引き継げない
- キャラクター切替後は旧セッションが破棄され、受付から新規作業を開始できる

### 設定事故テスト（本番では行わない）

テスト環境で必要な場合のみ、設定を一時的に不正値へ変更し、
resource再起動時に新規受付が安全停止することを確認します。

検出対象:

- 空の鉱石テーブル
- 重複した鉱石ID
- 0以下のweight
- 負のvalue
- 0/小数の容量
- min > max の採掘量
- 異常な作業時間
- 重複した採掘node ID
- 不正な座標
- 過大なサーバー距離許容値


## 受付からの作業終了 UX

未処理・未売却の鉱石がない状態で受付へ戻る。

- 受付に `[E] 作業状況を確認  [G] 鉱山作業を終了` が表示される
- Gで作業終了できる
- 終了後は採掘地点へのGPSルートが消える
- 再度Eで新しい作業を開始できる
- 原石または精製鉱石が残っている場合は、既存のサーバー側保護により終了できない

`/mine_end` は引き続き補助コマンドとして利用可能。
