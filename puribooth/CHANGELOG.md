- 管理job、ACE、入金先口座、履歴resourceを環境別に指定可能に整理。
- `Config.BoothRoutingBucket` で利用・撮影状態・同期・管理操作を一つのbucketに限定。既存DB形式は変更しない。
- 回収復旧・環境差異・routing bucketの静的回帰テストを追加。実銀行・隔離DB検証は未実施。

## 1.0.7 - 2026-10-28

### 撮影中の誤攻撃防止
- 撮影準備／カメラ確認画面の背景・床再選択キーをRからHへ変更
- 撮影者の準備・カメラ確認・撮影中は攻撃、近接攻撃、武器発射、リロードを無効化
- 撮影終了・中止後は通常操作を自動復帰
- UIの操作案内と日本語受入テストを更新
- PuriPhoto連携、撮影枚数、金融・会計処理は変更なし

## 1.0.6 - 2026-10-27

### 売上回収権限の厳格化
- `/puribooth collect all` / `/puribooth collect <台ID>` をWeazel jobの最上位grade（オーナー）のみに限定
- 最上位gradeは固定値ではなくQBoxのWeazel job定義から動的に判定
- `group.admin` / `group.god` のACE権限でも売上回収だけはバイパス不可
- 設置・撤去・料金変更・売上確認など、売上回収以外の管理権限は従来どおり維持
- `Config.Management.ace` 行の区切りカンマ位置を修正し、Lua構文を正常化

## 1.0.5 - 2026-10-27

### Flecity運営提出向け
- Weazel所属者に加えて、ACE `group.admin` / `group.god` を持つ運営権限者もFLEPURI管理コマンドを使用可能に変更
- 本番のWeazel job権限制御は維持しつつ、運営による設置・撤去・料金変更・売上確認・売上回収を可能に整理
- 運営提出パッケージ向けの導入・権限説明を更新

## 1.0.4 - 2026-10-27

### QBox互換性 / テスト環境修正
- QBox全体のリリース番号 2.5.4 と qbx_core リソース版番号を誤比較していた互換性判定を修正
- qbx_coreは版番号の固定比較ではなく GetJobs / GetJob / GetPlayer の必要exportsを実体確認する方式へ変更
- qbx_core v1.24.0の正常環境を誤って課金停止する問題を解消
- バニラQBoxにweazel jobがないテスト環境向けに、サーバーコンソール専用のruntime Weazel補助を追加
- `puribooth_dev_weazel [server_id]` で不足時だけ仮jobを作成しテスターへ付与
- `puribooth_dev_weazel_restore [server_id]` でテスト前のjobへ戻し、FLEPURIが作成したruntime jobを撤去
- 本番の管理権限は引き続き `Config.Management.job = "weazel"` をサーバー側で検証

## 1.0.3 - 2026-10-27

### 提出前最終安定化
- v1.0.2で退行していたPuriPhotoの二段階receipt確認（Get→Confirm→Consumed）を復元
- PuriPhoto production bundle / client bridge検査を強化し、confirm callback欠落時は課金前に停止
- PuriPhoto handoff timeoutをConfig化し、3〜60秒の範囲をselftestで検証
- 会計整合性 `lifetime_sales = balance + collected_total` のselftestを復元
- 撮影完了 / キャンセル / 切断 / タイムアウトの終端処理をsettlement lockで直列化
- 直接返金の同時実行をrefundInProgressで防止
- 有料セッションの監査ログ保存に失敗した場合はセッションを開かず返金へフォールバック
- resource stop時に売上 / 返金の結果が不明なセッションはprocessingへ隔離し、二重返金を防止
- `puribooth_refund_review` を追加し、照合済み返金をDB直接編集せず解決可能に変更
- 会社売上回収専用 `puribooth_collections` 台帳を追加
- 台残高の確保 / 復元 / 回収確定をoxmysql transactionで原子的に処理
- 銀行呼び出し境界をpaying / finalizing / restoringで分離し、クラッシュ後の二重入金を防止
- `puribooth_collections` / `puribooth_collection_retry` / `puribooth_collection_review` を追加
- 未解決の会社売上回収がある間は新しい回収と台撤去を停止
- updaterのPuriPhoto build guardでもconfirm receipt bridgeを必須化
- 不具合修正・復旧は開発側で行えるようSUPPORT.mdを拡充

## 1.0.2 - 2026-10-27

### 保守・復旧強化
- 撮影準備期限切れ直後にbeginCapture / 新規startSessionが競合すると返金せずセッション解放される可能性を修正
- 返金export失敗を `puribooth_refunds` に永続化し、pendingを自動再試行
- 自動返金はprocessing→resolvedの状態遷移を使い、異常終了時の二重返金を抑止
- 課金 / 売上 / 返金を `puribooth_events` に監査記録
- `puribooth_support` / `puribooth_refunds` / `puribooth_retry_refunds` を追加
- 未解決返金が残っている場合selftestをFAILに変更
- 想定外finishSessionイベントで有料セッションを無条件解放しないよう防御
- 監査ログ / 解決済み返金に保持期限を追加（既定90日）
- 返金workerのDB例外時もロックが残らないよう保護

# 開発中の会計復旧修正

- `safeAuditDetail` を最初の利用より前に定義し、回収状態遷移時の nil 参照を防止。
- 売上回収と保守回復コマンドに相互排他を追加し、精算途中の `preparing` 行を誤って閉じる競合を防止。
- `finalizing_retry` / `restoring_retry` の回復トークンと状態条件付きDBトランザクションを追加。再実行は銀行へ送金せず、回収台帳と各台の集計更新を一度だけ行う。
- Renewed-BankingとokokBankingV2を異なるexport契約の明示設定アダプターとして分離。外部入金結果が不明な場合は台残高を戻さず `paying` で手動照合へ回す。
- この変更はローカル回帰試験段階。実DB・実口座・FiveM実機では未検証であり、テストサーバーへの適用対象外。
