FLEPURI / フレプリ v1.0.3
Flecity operator submission package
Release date: 2026-10-27

Primary resource:
  puribooth v1.0.3

Compatible PuriPhoto runtime:
  puriphoto v1.1.1
  production bundle: ui/dist/assets/puriphoto-v1.1.1-flepri.js

Required runtime:
  qbx_core 2.5.4+
  oxmysql
  lb-phone
  screenshot-basic
  puriphoto 1.1.0+ with FLEPURI booth-import bridge
  Renewed-Banking (default company-sales payout mode)

Safety:
  No payment starts when qbx_core / PuriPhoto compatibility cannot be verified.
  PuriPhoto production JS/CSS/client bridge are checked by puribooth_selftest.
  FLEPURI closes its editor only after PuriPhoto NUI confirms image consumption.
  Failed handoff keeps the completed image and edit state in FLEPURI.
  Per-booth and per-player start locks prevent duplicate start charging.
  Sale-record failure falls back to refund.
  Pre-capture disconnect refunds by citizenid.
  Failed refunds are persisted and retried automatically.
  Ambiguous refund states stop in processing to avoid double refunds.
  Payment / sale / refund events are retained for support tracing.
  Terminal session settlement is serialized to prevent sale/refund races.
  Company-sales collection uses a crash-safe recovery ledger and DB transactions.

Management:
  Default job: weazel
  Commands: /puribooth place|remove|list|price|sales|collect

Sales:
  Per-booth price / pending balance / lifetime sales / completed count.
  Renewed-Banking payout account: weazel.
  Successful collections are also recorded in bank transaction history.

Database:
  puribooth_booths / puribooth_events / puribooth_refunds / puribooth_collections are created automatically.
  No manual SQL import is required.
  puribooth_selftest checks required schema columns.

Fonts:
  Font binaries are intentionally NOT included.
  Missing optional fonts use fallback fonts.
